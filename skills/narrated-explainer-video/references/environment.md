# 环境检查与首次搭建

在准备实现、预览或渲染视频，而环境尚不明确时阅读。仅讨论选题、口播稿或视觉方案，不需要安装软件。

## 先判断缺的是哪一层

| 情况 | 应采取的动作 |
| --- | --- |
| 没有 Remotion 指导 skill | 使用 Remotion 实现时安装官方 `remotion-best-practices`；缺少指导文件不等于运行环境缺失 |
| 没有 Node.js 或包管理器 | 先检查系统与项目兼容要求，补齐运行环境 |
| 已有工程但依赖未安装 | 按原包管理器与锁文件恢复依赖，不新建工程覆盖 |
| 完全没有工程 | 在合适的空目录或新子目录初始化项目 |
| 能启动 Studio，但不能渲染 | 检查渲染浏览器、系统依赖、字体与媒体加载，先修复测试帧 |

本 skill 是工作方法，不捆绑 Node.js、Remotion、浏览器或图片生成服务。安装 skill 不代表这些组件已就绪。

## 权限前提

搭工程、装依赖、下载渲染浏览器、调用素材生成服务，都需要真实的写文件与执行命令权限。

开工前先确认当前会话拿到的权限足够（能在项目目录外写缓存与临时文件、能启动子进程）。发现被拦时先向用户说明需要放开，不要反复试错绕路——排查本身比申请权限更费时间。

## 1. 盘点与补齐运行环境

检查操作系统、架构、工作目录的实际内容（包括隐藏文件）、已有 `package.json`、锁文件、Remotion 入口与正在运行的预览。不要把含音频、字幕、`.git` 或 `.env` 的目录视为空目录。

检查 Node.js、项目使用的包管理器以及脚手架可能需要的 Git，例如：

```sh
node --version
npm --version
git --version
```

已有工程优先遵循 `engines`、版本配置和锁文件。新环境选当前受支持且与目标 Remotion 兼容的 Node.js LTS，核对官方系统要求；不要将某个最低版本永久写死。缺少时使用该机器已有的版本管理器或适合系统的官方安装方式补齐，避免覆盖其他项目正在使用的默认版本。安装后重新检查命令与版本。

项目内依赖安装、浏览器下载与必要的环境配置属于已授权视频制作的准备工作，按当前环境权限执行；只有遇到真实权限限制或用户明确要求先批准时再停下说明具体阻碍。不要仅因缺少软件就把全部安装工作交回用户。

辅助脚本另有依赖：`inspect_media.py` 需要 Python 3，传入 `--audio` 时需要 `PATH` 上可执行的 `ffprobe`。Remotion 本身可通过自身命令提供媒体工具；不要混淆这两者。若不安装独立 FFmpeg，可先只用脚本处理 SRT，再使用项目里的 `npx remotion ffprobe` 单独核对音频。该 Python 脚本不会自动调用 Remotion 的工具。[官方 FFprobe 命令](https://www.remotion.dev/docs/cli/ffprobe)

在 Windows / PowerShell 这类引号与变量展开规则复杂的环境下，把自动化脚本写成独立的 `.py` / `.mjs` 文件再执行，不要用 shell 内联命令（heredoc、`-c` 长字符串等）：转义会改坏脚本内容，出错时很难分辨是脚本逻辑问题还是命令行转义问题，还容易误改到别的文件。macOS / Linux 的 sh 没有这个问题，可以直接内联。

## 2. 复用或初始化工程

**已有工程：** 沿用其包管理器、锁文件和脚本。依赖缺失时，使用锁文件对应的确定性安装方式，例如 npm 项目的 `npm ci`；若锁文件与清单不一致，查明原因再处理，不能为省事删掉锁文件。无锁文件时按项目规范安装并生成锁文件。缺少的 `remotion` / `@remotion/*` 包使用与工程一致的版本，避免把 `latest` 混入旧工程。

**没有工程：** 先选择不覆盖现有资料的位置。下面是 npm 的新项目示例；`explainer-video` 应替换为合适的新目录名，包管理器按实际环境调整：

```sh
npx create-video@latest --yes --blank explainer-video
cd explainer-video
```

检查脚手架是否已成功安装依赖；未安装时再运行 `npm install`。不要不加判断地重复安装。具体命令与系统支持以执行时的 [官方创建项目文档](https://www.remotion.dev/docs/) 为准。只有确认当前目录确实为空时，才考虑直接在当前目录初始化。

使用 Remotion 制作时，安装并读取官方 `remotion-best-practices` skill：项目仓库提供联合安装脚本，也可参考 [官方 Agent Skills 文档](https://www.remotion.dev/docs/ai/skills) 单独安装。它不是 JavaScript 运行依赖；已有时直接读取。补装时选择与本 skill 相同的助手及安装范围，不默认覆盖用户已有的修改。若安装受阻，说明限制，使用官方文档继续可以完成的工作。

## 3. 准备浏览器、字体与媒体

在项目目录中确认渲染用浏览器可用：

```sh
npx remotion browser ensure
```

Remotion 可管理其渲染浏览器；Linux 等环境可能还需要对应系统依赖。按照当前系统与版本修复，不复制其他机器的浏览器绝对路径。[官方浏览器准备文档](https://www.remotion.dev/docs/miscellaneous/chrome-headless-shell)

加载本片需要的字体并检查实际字形，尤其是中文、特殊符号和多语言。**优先枚举本机已安装的字体**：确认有合适的字重后直接写进样式，不要默认依赖在线字体服务——离线、跨网络或字体包过大时，它会让预览和渲染一起失败。确认图片、音频路径可被预览和渲染读取，不依赖临时失效链接。生图服务仅在需要生成素材时准备，没有生图能力仍可先用代码图形完成适合的解释画面。

## 4. 先验证最小工程，再做整片

启动项目已有的 Studio 脚本，或在合适工程中运行：

```sh
npx remotion studio
```

打开终端实际输出的地址，不写死端口。确认 Studio 页面和组合预览确实加载成功；让预览在制作期间保持可访问。若脚手架还没有可用组合，先注册一个最小测试组合。

然后检查可用组合，并用实际 ID 渲染一个测试帧（输出目录先确保存在）：

```sh
npx remotion compositions
npx remotion still CompositionId "/project/output/setup-check.png" --frame=0
```

查看测试帧，确认字体与素材正常；有正式音频时在预览中检查可播放。用户已经要求交付成片且需要验证音轨编码时，可额外导出几秒测试片段；只要求方案或预览时不默认渲染完整视频。

环境就绪的依据是：依赖可用、预览实际打开、测试帧成功且可查看、所需字体和媒体可读取。单纯“安装命令退出成功”不等于制作链路已经打通。

如果仍失败，记录具体命令、错误和已完成部分，修复对应层；不能假称就绪。网络或权限暂时阻塞时，可以继续不依赖环境的内容与分镜工作，并明确尚未验证的制作能力。
