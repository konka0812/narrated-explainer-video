# 实现与同步

在接收音频字幕、编写视频工程、替换最终输入或导出时阅读。以下以 Remotion 为常用实现方式，不要求已有项目迁移。

进入工程实现后，若是首次使用或环境不可运行，可按[环境检查与首次搭建](environment.md)定位缺项。

## 检查输入

本 skill 的脚本使用 Python 3 标准库；带 `--audio` 时需要本机可运行的 `ffprobe`。把命令中的 `<skill-dir>` 替换为本 skill 的实际目录，其余输入输出路径也替换为当前项目路径：

```sh
python3 "<skill-dir>/scripts/inspect_media.py" \
  --srt "/project/input/captions.srt" \
  --audio "/project/input/narration.mp3" \
  --fps 30 \
  --output "/project/timeline.json"
```

不传 `--audio` 时只检查字幕，不声称验证过音轨；不传 `--output` 时 JSON 输出到标准输出。支持 `--fps 30000/1001` 等分数帧率。查看 `--help` 获取实际选项。

`--audio` 读取第一条音轨。旁白在其他轨道，或工具无法从容器中可靠确定这条音轨的时长时，可单独导出旁白再检查。

JSON 中 `cues` 保留原文、原字幕 ID、毫秒时间与 `startFrame` / `endFrame`；帧位置按绝对时间就近取整，半帧向上，终点排他。`minimumDurationFrames` 覆盖已知音频、字幕和帧边界；未提供音频时它不能代表最终成片长度。

`warnings` 会提示字幕的实际重叠时长、空字幕、超过 3 秒的间隔及字幕超出音频等情况，是否需要调整由内容决定。SRT 可以有多行正文，各条字幕之间用空行分隔。若正文里又出现下一条的编号和完整时间行，工具会报出缺少空行的位置。解析失败时会保留输入和已有输出。写入文件时请指定已存在的父目录。

### 铺开分镜前先听几句

同时拿到旁白和 SRT、需要将动作对齐发声时，优先抽听用户说改过的句子。整条旁白换版时，可以在开头、中间和接近结尾各找一个容易听辨的短语，连着前后停顿播放，比较实际发声、字幕出现和准备触发动作的时刻。已核过的音轨只做局部排版时，可直接从修改时段开始。

发现偏差时，比较相邻句和后段的表现，判断是整段偏移、越往后越偏，还是只有一句措辞变了。保留原时间码，说明具体句子、时段和影响，按用户指定的版本处理。结构检查和抽听各能说明一部分情况，交付时按实际播放范围记录。

## 工程组织

先检查现有项目的依赖、组合入口、组件和素材路径。新项目再选合适的结构，例如：

```text
project/
  input/                   最终音频、字幕；也可使用项目现有目录
  storyboard.md            逐句映射与设计决定
  src/
    scenes/                按语义段落划分的组件
    captions/              保留 ID 与原始时间的字幕数据
    shared/                字体、颜色、字幕、公共图形
  public/                  实际引用的媒体
  output/                  成片及按需制作的发布素材
```

结构只是示例，避免为每期复制整套依赖。共享工程的素材、字体和组件应保留明确归属与引用。

## 素材与生成数据

处理用户配图、截图、录屏、实拍视频，或需要生成插画、抠图和角色状态时，阅读 [素材设计与复用](assets.md)。保留原素材、选用区域、处理结果与关键参数，避免整张图替代所有镜头的解释动作。

字幕数据从用户指定的最终 SRT 生成，保留原文、ID 与绝对时间。修改字幕后重新生成数据，不在生成物里临时改字以免下次被覆盖。SRT 是这份字幕数据的来源；实际节奏仍需与音频核对，知识点与新闻结论仍需核验资料。

## 接入真实视频片段

先记录原片时间中的取段起止、关键动作和结果，再映射到成片场景。明确场景局部时间、原片时间、原片帧率和成片帧率，按照所用视频组件的实际语义处理裁剪与变速，避免混用帧单位或重复扣除起点。

例如原片中选用的有效动作段长 6 秒、成片给它 3 秒，匀速放完约需 2 倍速；但若关键文字因此读不清，应修剪等待或调整分镜，而非只套比例。结果出现后可定格停留，再接下一句。改变速度后重新核对动作与强调时刻，不能沿用旧的点击时间。

媒体保持等比，局部放大、裁切、圆角和遮罩放在清楚的容器层中。高亮、指针或标注与素材共享对应坐标变换，避免素材已经移动而标注仍停在原处。按需处理素材原声，检查被引用媒体可加载且有足够帧数覆盖所选片段。

片段接入后连续检查“操作前 → 操作 → 反馈 → 结果”，尤其是网页加载和片尾。播放器能解码、静帧有画面，不代表这一过程已完整展示；裁切、变速、定格与音频同步应在实际预览中验证。

## 让常用视觉参数便于修改

把复用的颜色、字体、字幕区、间距、圆角和阴影等整理为主题参数与共享组件。用背景色、文字色、强调色等语义命名，减少换风格时重复修改场景。

特定对象的固有颜色、图表含义色或局部几何可以保留在对应组件，不要求所有数值都集中到一个文件。整体换风格时还需检查构图、素材和动作语言，不能只换颜色就视为完成。修改主题后回看典型镜头，确认对比、换行与字幕空间仍正确。

## 帧与时间

- 从绝对时间计算每条字幕、场景和动作的帧位置，统一舍入方式；不要把逐句四舍五入后的时长相加，否则长视频会累积漂移。
- 帧区间采用起点包含、终点不包含。小于一帧的字幕至少给一帧，并检查它是否真的可读。
- 总帧数覆盖最终音频与有效视觉内容。通常对最长时间乘帧率后向上取整；片头片尾留时单独声明，不默默截断旁白。
- 全局时间用于字幕与场景衔接，局部时间用于场景内部动作；嵌套 Sequence 时明确偏移，避免重复扣除起点。
- 只有逐句 SRT 时，词语级强调需听取定位或另做对齐，不能把均匀拆分当成真实词时间。

动画应由帧决定，使同一帧可重复渲染。使用当前帧、插值、弹簧和受控随机数；不要用实际时钟或非确定性循环驱动导出。加载字体、图片和其他异步资源时使用当前工程支持的等待方式。

具体 API 以安装版本和本地类型为准；需要外部文档时查官方资料，不凭空假定导出名称。已安装的 Remotion skill 可用于详细 API、字幕、音频和转场实现。

## 制作顺序

先搭建完整音轨、字幕与场景时段，再制作代表性动作并推广到全片。有目标时长时，在铺开全片动画前，按最终播放语速核对完整旁白的实际时长。项目自行录制或合成旁白时，记录音色、语速和生成方式，便于局部补录。共享样式可以统一字体、色彩和字幕，但不把所有句子锁进一个版式。

需要新选旁白音色时，可用同一段有代表性的短稿试读，比较咬字、重音、停顿和表达是否适合内容。选定后保存试音和必要参数，按定稿制作正式旁白，再用完整音轨对齐字幕和动作。

将时序写为可读数据或常量，而不是散落的“神秘帧数”。主要对象拆为可运动层，按口播触发局部变化；需要时给用户查看短预览。

音效和背景音乐按内容及用户需求加入，旁白优先。不能为了显得热闹为每个元素添加提示音。

## 更新输入

保存新旧输入的区别。可分段替换旁白时，复用未改的录音，检查新旧录音在接缝处的音色、响度和停顿，并以拼接后的完整音轨为准。按最新输入重新生成时间轴，核对受影响的字幕内容和时间、场景起止、动作触发点、结尾、音频路径和总帧数。对于仅措辞变动的句子，复用仍正确的场景。

旁白变速、拼接或补录后，用最终播放语速连听接缝和转折处，检查意外长空白、句间贴得太紧和句尾被切掉。静音检测可定位疑似长空白，再结合前后句试听判断停顿是否合适。调整后以新的完整音轨更新受影响的时间轴。

## 导出

使用项目已有的构建与渲染命令，先确认组合 ID 与输出路径。常见调用形态：

```sh
npx remotion compositions
npx remotion render CompositionId "/project/output/final.mp4" --codec=h264 --audio-codec=aac
```

根据平台和用户需求选择编码、画幅和质量，验证当前版本支持相应参数。不要把某台机器的浏览器路径、端口或并发数固定进项目。需要资源限制时根据运行环境调整。

用户明确要求交付成片时完成导出；只要求方案或预览时不把昂贵的全片导出作为默认步骤。
